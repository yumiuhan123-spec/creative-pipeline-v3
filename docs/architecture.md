# 架构说明

Creative Pipeline V3 的核心目标不是“把所有事都自动化”，而是把复杂判断、确定性脚本、人工审核和运行状态分清楚。

## 四个室

### 开发室

开发室就是源码仓库。它只保存工具本身：

- Skill
- 模板
- 脚本
- 文档
- 测试
- 版本管理器设计

不要把真实产品素材、运行结果、浏览器登录数据放进开发室。

### 模板室

模板室是 `template/main-image-project`。它是一份干净母版，只包含：

- 空文件夹
- 默认说明
- 默认配置
- 可编辑提示词
- 初始状态文件

模板室不能包含真实产品资料和运行结果。

### 工作室

工作室是用户从模板复制出来的具体产品项目。这里允许出现：

- 真实输入素材
- 分析结果
- 三套候选方案
- 人工选择记录
- 最终提示词
- 浏览器分发记录

工作室不应该反向修改模板室。

### 档案室

档案室保存历史版本快照。它用于复盘、分享和回滚，不用于日常开发。

推荐位置：

```text
%USERPROFILE%\Desktop\创意资产流水线_版本档案
```

## 职责边界

```text
Codex：理解资料、分析、方案组合、提示词写作、解释和人工沟通
脚本：安装、检查、复制、清单、启动 Edge、分发提示词
用户：提供资料、审核方案、选择方向、确认是否提交
```

成熟度判断标准：

```text
不是“当前对话里的 Codex 能跑通”，而是“新对话、新机器、少量上下文也能按文档复现”。
```
