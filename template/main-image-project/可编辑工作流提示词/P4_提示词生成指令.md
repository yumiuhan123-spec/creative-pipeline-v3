# P4 六张主图提示词生成指令

## 你的任务

基于已经人工确认的最终方案，为六张主图分别编写可直接提交给 Image 2 一类图像大模型的自然语言提示词。

提示词是给能够理解完整自然语言、任务目标和参考图片关系的大语言图像模型使用的。不要写成 Midjourney 风格关键词串，不要使用权重符号、参数尾巴、正向词列表或反向词列表。

不要只在聊天中输出提示词。每张提示词必须保存为独立文件。

## 执行前必须读取

1. `00_project/project.yaml`
2. `00_project/status.json`
3. `00_project/category_library/主图类别定义.md`
4. `01_inputs` 中最终方案引用的产品与品牌资料
5. `03_analysis/evidence_table.md`
6. `05_selected_scheme/selection_notes.md`
7. `05_selected_scheme/selected_scheme.md`
8. `06_prompts/draft/提示词写作模板.md`

如果 `selected_scheme` 仍为未确认、不是六张图，或引用了不存在的证据和文件，停止 P4 并报告问题，不要自行替用户完成选择。

## 提示词写作原则

1. 使用连贯、明确、可执行的自然语言。
2. 先说明商业目标，再说明产品一致性、画面内容、构图、文字区域、限制和验收标准。
3. 明确每个参考文件的作用，例如识别产品结构、保持颜色、参考包装或参考 Logo。
4. 区分“必须保持不变”和“允许模型自由设计”的内容。
5. 明确人物、动作、场景和产品之间的逻辑关系，避免只罗列名词。
6. 描述构图时说明主体位置、镜头距离、视角、留白、层级、光线和配色目的。
7. 页面文字只使用经过确认的内容。对图像模型难以稳定生成的长文字，应要求预留清晰排版区域，而不是生成大段小字。
8. 产品外观必须以产品参考图为准，不得擅自增加按钮、开孔、配件、材质、结构或品牌标识。
9. 不得虚构认证、检测、数据、评分、销量、客户数量或服务承诺。
10. 六份提示词必须分别独立完整，不能依赖“同上”“延续上一张”等上下文。

## 每份提示词必须覆盖

- 图片在六图序列中的编号和商业任务
- 目标买家以及希望消除的顾虑
- 产品参考图及其用途
- 必须保持准确的产品特征
- 场景、人物、动作、辅助物和背景
- 主体位置、镜头、构图和视觉阅读顺序
- 光线、色彩、质感和整体商业风格
- 标题或短文案，以及应保留的排版区域
- 允许调整的内容
- 禁止改变和禁止虚构的内容
- 最终验收标准

## 输出步骤

1. 先将六份提示词写入：
   - `06_prompts/draft/01.txt`
   - `06_prompts/draft/02.txt`
   - `06_prompts/draft/03.txt`
   - `06_prompts/draft/04.txt`
   - `06_prompts/draft/05.txt`
   - `06_prompts/draft/06.txt`
2. 更新 `06_prompts/prompt_overview.md` 和 `06_prompts/prompt_index.json`。
   在 `prompt_index.json` 中为每张图记录需要上传的项目内参考文件路径。
3. 停止并等待人工检查。
4. 人工确认后，将对应内容写入：
   - `06_prompts/final/01.txt` 至 `06_prompts/final/06.txt`
5. 将 `prompt_index.json` 的状态更新为 `approved`，记录确认时间。

不得在未获人工确认时，用草稿覆盖 `final`。

停止等待人工检查时必须明确告诉用户：

- 六份草稿位于 `06_prompts/draft`。
- 可以双击 `人工审核区/03_打开提示词草稿.cmd` 逐份查看和修改。
- 浏览器最终读取的是 `06_prompts/final`，此时不得提交。

## 浏览器提交条件

只有同时满足以下条件才允许进入浏览器阶段：

- 六个 `final/*.txt` 均不为空且不包含模板占位文本。
- `prompt_index.json` 状态为 `approved`。
- `00_project/status.json` 中 `prompts_approved` 为 `true`。
- 用户已经批准提交浏览器任务。
