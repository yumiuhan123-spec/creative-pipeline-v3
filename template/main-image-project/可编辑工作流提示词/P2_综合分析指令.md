# P2 综合分析指令

## 任务

综合分析 `01_inputs` 中的产品事实、图片、竞品、评论、市场、买家与品牌资料，形成可追溯的主图策略依据。分析必须写入文件，不要直接跳到方案。

## 执行前读取

1. `00_project/project.yaml`
2. `00_project/status.json`
3. `00_project/category_library/主图类别定义.md`
4. `02_inventory/input_manifest.json`
5. `02_inventory/missing_information.md`
6. `02_inventory/source_notes.md`
7. `01_inputs` 下清单标记为有效的资料

只有 G1 输入确认完成后才能执行。

## 分析要求

1. 区分产品事实、用户反馈、竞品表达和分析推断。
2. 提炼产品核心功能、差异、目标买家、使用场景、购买动机与顾虑。
3. 从竞品主图中总结信息结构与表达规律，不复制品牌、文案、数据和独特设计。
4. 从评论中区分高频痛点、满意点、误解、反对意见和未满足需求。
5. 判断五类主图分别适合承担哪些商业任务。
6. 为每个可能进入方案的卖点建立证据编号。
7. 明确所有不可使用、需要确认或证据不足的宣称。
8. 当资料冲突时记录冲突，不自行选择对产品更有利的版本。

## 输出

将完整分析写入 `03_analysis/analysis_result.md`，至少包含：

- 产品事实
- 核心购买动机
- 主要痛点与顾虑
- 竞品表达规律
- 差异化机会
- 评论洞察
- 买家与使用场景
- 可用视觉证据
- 风险与禁用内容
- 六图叙事策略建议

将逐条证据写入 `03_analysis/evidence_table.md`。每个证据必须指向具体来源文件。

完成后将状态设为 `ready_for_scheme_generation`，随后可以执行 P3。
